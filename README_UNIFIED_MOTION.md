## 2. 控制结构

```text
黑线 / 绕障 / 八字 / 正方形
             |
             v
  左右 CPS 或四轮位置目标
             |
             v
 DriveBase 四轮速度/位置反馈
             |
             v
 motorPWM.c（唯一方向映射和 PWM 硬件层）
```

`Core/Src/drive_base.c` 是唯一允许运行模块调用 `pwm_motor*()` 的执行层。
`motorPWM.c` 的实车方向映射和三节点功率标定没有修改。旧 `motor.c` 已从
手动构建和 CubeIDE Debug/Release 构建中排除。

## 3. 编码器

TIM6 上电后以 20 kHz 常驻采样，动作之间不再停止、重新配置或清零；每个
动作保存自己的起始快照。逻辑符号统一为车辆前进为正：

| 轮 | 引脚 | 原始计数修正 |
|---|---|---:|
| M1 | PD12/PD13 | `+1` |
| M2 | PA15/PB3 | `+1` |
| M3 | PA0/PA1 | `-1` |
| M4 | PB4/PB5 | `-1` |

软件同时累计合法正交变化、非法双位变化、方向不一致次数和最近有效运动
时间。方向不符、持续非法变化、失速、动作超时或轮间进度差过大都会停止。
新符号仍必须先通过悬空正反转确认；编译不能证明物理方向。

## 4. 连续速度控制

- 周期：20 ms。
- 每轮独立使用分段前馈加 PI 修正；输出饱和时执行抗积分饱和。
- 目标变化使用 CPS 斜坡，不从停车一步跳到最大速度。
- 只有确认静止的落后轮才允许一次错峰启动补偿；补偿后仍无计数最终会
  触发失速，而不会无限重复高功率脉冲。
- 前进和反向的最小稳定 PWM、补偿 PWM 分开存放；当前反向初值沿用正向
  数据，尚待有载荷反向标定。

## 5. 低速位置脉冲与四轮同步

短距离、小角度、末端接近和低速弧线内轮不再使用按目标累加的固定
`3100/3300 PWM` 脉冲密度。DriveBase 每次脉冲前读取剩余计数，按该轮
上次实际增量调整脉宽和 PWM；脉冲后等待编码器稳定再继续。

直线和转向均按 `moved_i / target_i` 比较归一化进度。领先轮减速或跳过
脉冲，落后轮只获得有限补偿；任一轮进入到站容差后，其余轮也只能使用
有界位置脉冲，避免三轮停止而最后一轮持续高功率。所有活动轮进入容差
后统一停车。

## 6. 各模式

| 入口 | 上层功能 | 底层控制 |
|---|---|---|
| KEY1 / `1` | 黑线循迹 + 红外/超声波绕障 | 黑线外环 + 四轮速度内环；绕障段为四轮位置反馈 |
| KEY2 / `2` | 仅黑线循迹 | 黑线外环 + 四轮速度内环；丢线 360° 为位置反馈 |
| KEY3 / `3` | 一次八字后停车 | 220 mm 半径初值；四轮同步位置反馈，低速内轮用位置脉冲 |
| 遥控/串口 `4` | 400 mm × 4、90° × 4 正方形 | 四轮同步位置反馈 |
| 遥控/串口 `0` | 锁存停车 | 立即撤销动作 |

K210 当前保持禁用，但 USART2 和视觉事件代码未删除。红外状态 RGB、超声
蜂鸣器、五音节蜂鸣器优先级仲裁、OLED 电量显示、蓝牙/串口和实体按键均
保留。

丢线恢复已改为编码器闭环快速后轴支点搜索：M1/M3 两个前轮反向转动，
M2/M4 两个后轮保持零输出，使车尾依靠轮胎摩擦近似固定、车头扫过黑线；
八字、正方形和绕障仍使用原来的四轮通用转向。搜索轮速由 1800 提高到
3600 counts/s。X2/X4 外侧探头只作为接近黑线的预告，不能再终止搜索；
只有 X1/X3 中间探头连续确认 12 ms 后，才受控制动并进入 250 ms 低速捕线。
若制动或捕线期间只剩外侧探头/再次全白，则保持原预测方向继续搜索，不会
先向前点动。该逻辑仍保留单次最多 360° 的安全上限。

重捕交接在 2026-09-04 进一步缩短：保留 DriveBase 的 30 ms 换向保护和
22 ms 反向转矩制动，制动完成后的下一控制周期即进入低速捕线，不再等待
位置模块通用的 90 ms 静止观察，也不再叠加 70 ms 前进保护。该修改只作用
于已经确认中央探头压线的重捕路径；正常循迹、停车和其他位置动作的制动
时序不变。

## 7. 电压前馈与停车

电池滤波电压只给前馈 PWM 提供有限补偿：以 7.8 V 为初值参考，补偿限制
在标定值的 85%～115%；编码器反馈仍是闭环主体。电量百分比仍只显示，
不会擅自增加欠压停车。

`COAST` 使用原有 0/0 滑行。`BRAKE` 使用非阻塞的 30 ms 0-PWM 换向保护，
随后施加最长 22 ms、PWM 2400 的反向转矩，再恢复 0/0。由于尚未确认
AT8236 的 1/1 真值表，本版本明确不使用未经验证的 1/1 硬件制动。

## 8. CubeMX 风险

`.ioc` 已记录 TIM6（PSC=71、ARR=49、IRQ 优先级2）及八个编码器 GPIO。
当前运行代码仍由 `wheel_encoder.c` 手动初始化 TIM6。以后若用 CubeMX
重新生成，必须先备份，并将生成的 `MX_TIM6_Init()` 与手动初始化合并为
一套；同时保留唯一 `TIM6_IRQHandler`、唯一 `EXTI15_10_IRQHandler` 和
唯一 `HAL_GPIO_EXTI_Callback`。PA15/PB3/PB4 仍要求关闭 JTAG、保留 SWD。

## 10. 必须按顺序进行的实车验收

1. 上电默认停车，确认串口启动语包含 `EXP7 UNIFIED MOTION V1`。
2. 四轮悬空：分别验证前进计数全为正、后退全为负；查看 `DRV` 中目标
   CPS、实测 CPS、PWM、非法跳变和方向不一致计数。
3. 悬空低/中/高速与小角度动作；阻挡单轮时应先只补偿该轮，随后安全
   故障，数字0必须立即停车。
4. 地面低速直线，再测试左右15°各10次和左右90°各5次并记录电压。
5. 依次测试 KEY2、KEY1、KEY3 和正方形。编码器达标不等于车身角度或
   轨迹达标，打滑和负载仍必须实测。
