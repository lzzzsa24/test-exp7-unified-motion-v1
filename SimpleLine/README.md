# 简化四路寻线

本分支从硬件接口和已记录的电机标定数据重新编写应用。唯一控制链路是：
四路 GPIO → 采样去抖 → 左右侧 PWM → 四个电机。
无 RTOS，无速度/位置闭环，无回退轨迹；所有运行判断都在固定 5 ms 周期内完成。

分支：`feature/simple-four-line`。起点：`d2efe0e`。
回退标签：`rollback/2026-09-05-before-simple-four-line`。
取消超时停车前的回退点：`rollback/2026-09-05-before-continuous-simple-line`（1747620）。
该点的原固件保存在 `manual-build-simple-line-before-continuous-search`。

## 使用

以下定义适用于串口标识为 **SL2** 的持续寻线固件，本次修订尚未烧录。

| 输入 | 操作 |
|---|---|
| 上电、复位 | 停车，按住启动键上电也不会启动 |
| 实体 KEY1 或 KEY2 | 按一次启动持续寻线；启动时全白也会开始搜索 |
| 实体 KEY3 | 停车，按住时优先于所有启动来源 |
| 遥控器数字 1 / 2 | 启动；NEC 长按重复帧不重新启动 |
| 遥控器数字 0 / 3 | 停车 |
| 串口字符 `1` / `2` | 启动 |
| 串口字符 `0` / `3` / `s` / `S` / 空格 | 停车 |
| 串口 `?` | 查询状态 |

串口为 USART1，PA9 TX / PA10 RX，115200、8N1。连接前枚举实际串口号。
遥控/实体/串口没有不同驾驶模式；KEY3 已不再执行八字。
启动后无须反复按键。丢线持续搜索，重新看见线便恢复循迹；只有人工停车才退出运行。
人工停车后看见黑线也不会自行启动，需重新发出启动命令。

## 决策表

四位始终按车头朝前时的**左外、左内、右内、右外**排列：`X2 X1 X3 X4`。
`1` 表示检测到黑线（引脚低电平），`0` 表示白底。
左右侧各两台电机接收相同逻辑 PWM，负数表示该侧倒转。

| 四路读数 | 动作 | 左 PWM | 右 PWM |
|---|---|---:|---:|
| `0110` | 居中直行 | 2400 | 2400 |
| `0100` | 向左微调 | 2200 | 2600 |
| `0010` | 向右微调 | 2600 | 2200 |
| `1000`、`1100` | 左急转 | -2700 | 2700 |
| `0001`、`0011` | 右急转 | 2700 | -2700 |
| `0000`，已有左右方向记录 | 沿上次方向持续原地搜线 | 按方向取 ±2700 | 与左侧反向 |
| `0000`，本次启动还没有方向记录 | 默认持续向左原地搜线 | -2700 | 2700 |
| 其余 8 种组合 | 宽线/交叉/分离检测，持续低速直行通过 | 2200 | 2200 |

急转、搜线、宽线通过都没有时长限制，也不会因输入抖动或调度延迟锁存停车。
搜索方向保留到新的有效左右读数出现，不随时间失效，不进行按时间左右交替搜索。
探头回到中间并经过两次一致采样后直接恢复循迹，无须再按启动键。
每次明确启动后的第一个读数用于立即决策，后续变化要求两次一致；持续抖动时沿用
上一个已接受的动作，不停车等待。运行中再按启动键不会重置搜索方向。
默认搜索方向在 `line_config.h` 的 `LINE_DEFAULT_SEARCH_DIRECTION` 中设置：-1 左、+1 右。

电机换向时先输出零，再等待至少 10 ms 才允许反向通电。
正常停车是 PWM 归零滑停，不代表机械瞬停。
本版不启动独立看门狗；不存在由看门狗超时复位造成的重新按键启动流程。
上电/复位保持 STOP，CPU 或时钟硬故障仍直接关闭 PWM 输出。

## 查看运行状态

USART1 每 200 ms 上报一次，状态切换和查询也尝试上报；发送繁忙时丢弃遥测，控制不等待串口。

```text
SL2 TRACK OK raw=0110 line=0110 L=2400 R=2400
SL2 SEARCH OK raw=0000 line=0000 L=-2700 R=2700
SL2 STOP USER raw=0000 line=0000 L=0 R=0
```

`raw` 是原始读数，`line` 是滤波后读数；`L/R` 是换向间隔和限幅后的逻辑 PWM，
不是编码器测速值，逐轮实际 CCR 还会经过标定映射。
状态原因只保留 `USER`（上电/人工停车）和 `OK`（运行）。
UART 溢出或帧错误会清除错误标志并丢弃损坏字节，不把通信错误当作停车命令。

LED1（PG13）表示运行，LED2（PG15）表示正在丢线搜索。
左右 RGB 的红/绿分量分别映射到本侧外/内探头，停车时也更新，便于移动黑纸核对接线。
状态原因变化会短鸣 100 ms。本版不刷新 OLED，不采集电池、编码器或障碍传感器。

## 验证与后续实车调整

已完成 Arm 编译、链接以及主机测试：16 种输入各持续运行 10 秒、左右各连续 5 分钟
丢线搜索、抖动时连续运行、跨越计时溢出和 60 秒调度延迟、重新见线自动循迹、
人工启停、GPIO 顺序、四轮正反极性、全 PWM 范围、换向间隔和遥控 STOP 到 PWM 归零。
以上持续运行时长均为主机**模拟时间**。串口发送繁忙时停车及错误字节处理也已验证。
主机用 HAL 寄存器替身验证软件行为，不模拟轮胎、惯性、电池或黑线。
CubeIDE 元数据已静态核对，未在本次运行 IDE 构建。

用户最新实车反馈：丢线立即停，有线时也走一下就停，需要不断按键才能缓慢前进。
该反馈已记录；缺少当时的串口停车原因和固件哈希，不能确定究竟触发了哪条旧停车路径。
本次已统一移除这些自动锁停机制，但修订版**未烧录、未悬空试车、未地面试车**。
PWM 设定未改，新的地面表现仍待观察。后续经明确授权烧录后：

1. 停车时逐一遮挡探头，核对左到右 `1000 → 0100 → 0010 → 0001`。
2. 悬空核对启动、左右急转的电机方向和 KEY3/遥控 0 停车。
3. 在同一地面、电池电压下测试直线、左右弯、持续丢线与重新见线，并确认遥控 0 能停车；
   串口前缀应为 `SL2`。
4. 只根据真实表现调整 `line_config.h`：急转起不来调转向 PWM，冲过线则降低速度；
   首先核实探头阈值和安装位置，再考虑增加控制逻辑。

适用目标是白底黑线的连续循迹。本版对岔路保持直行，不执行路线规划或避障。
