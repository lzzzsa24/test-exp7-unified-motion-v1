# 寻线过弯欠速补偿与停机诊断

## 现场问题与范围

用户报告：更换地面材质后，正常寻线过弯也吃力；KEY2 下经常停车、
黄灯、蜂鸣，然后保持不动。当前尚未取得蜂鸣次数或 DRV 故障码，不能
把报警直接认定为堵转，更不能认定本次补偿已消除报警。

本分支沿用 `2a7a5d5` 起点，增量父提交为 `bd78b62`。
集成任务已将前一轮恢复逻辑以 `aebf230` 集成并记录烧录。
用户本轮明确允许为寻线配套修改 `drive_base.c/.h`；不改变其他模式的
调参，不修改 PROJECT_STATE.md，不访问串口，不烧录，不操作小车。

## 原代码的限制

速度内环以目标 CPS 查表得到 PWM，再加限幅到 ±500 的 PI 补偿。
完全无编码器位移才触发现有的 80 ms 起步脉冲。车轮每个周期都缓慢
移动时，无运动计时会清零，因而不会触发这个脉冲。

例如在 7.8 V 标定参考电压下，2493 CPS 的前馈约为 2428 PWM；
持续 PI 校正最多再增加 500。这个软件上限是已确认事实，但没有电流、
电机负载曲线和现场反馈，不能据此计算真实转矩或证明唯一根因。

## 本次控制行为

- 保留正常寻线、低速捕获和搜索的目标 CPS，保留四轮方向与所有几何参数。
- 仅在一次已授权且实际接受的寻线差速/对转速度指令下启用。
  直行、宽线直行、停车、位置回溯/回退、其他模式不启用。
- 每轮独立判定：目标斜坡已到达所请求 CPS，目标至少 1412 CPS，
  编码器方向不反向，实测速度连续 40 ms 低于目标的 85%。
- 额外 PWM 为 `min((目标速度幅值 - 同方向实测速度)/2, 600)`，
  每毫秒最多上升 5（20 ms 周期最多上升 100）。
  实测速度达到目标的 85%、反向、退出条件或样本过期，立即清零这部分补偿。
  不提高轮速目标，不把编码器测速误称为电流/转矩闭环。
- 总输出仍限制在硬件的 ±3599 PWM；额外补偿参与原有饱和防积分累积判断。
  原有短时起步脉冲优先，不与这部分额外 PWM 相加。
- 准备接口本身不产生运动。只有随后 20 ms 内完全匹配的四轮目标可以
  消费一次准备；不同目标（包括上层减速）、拒绝的命令或普通调用取消补偿。
  已接受的授权 60 ms 不更新即失效；停机、故障、位置动作会清除它。

这是面向欠速的初始有界参数，不是针对某种地面的实车标定。车轮已经
快速空转但车身不转时，不会因为车身转角不足而继续增加这部分 PWM。
反向位置回退仍使用原 DriveBase 位置控制和脉冲起步策略；如果故障来自
回退超时、同步或编码器异常，这次速度模式补偿不保证解决。

## 黄灯、蜂鸣和锁存

当前 main.c 的 KEY2 驱动故障分支在 `DriveBase_GetFaultMask()!=0` 时：
按每组 2.5 秒的节奏输出短鸣，点亮红色通道和两个板载 LED，并跳过寻线。
该分支没有清除绿色/蓝色，原来的绿色与红色叠加可显示黄色。因此颜色
不是独立的故障码。KEY2 不经过 KEY1 的障碍物接管流程。

每组 1/2/3/4 声指向故障掩码中最先出现的 M1/M2/M3/M4 位，分别为
左前、左后、右前、右后；这只定位轮子，不区分堵转、反向或非法编码器信号。
没有轮位时 5 声对应超时位，8 声对应 DriveBase 同步故障位。
main.c 中高位蜂鸣映射的部分注释沿用了其他控制器的含义，诊断应以
drive_base.h 的掩码定义及 `DRV ... F=` 为准，不能照搬“转够 360 度”等注释。

DriveBase 掩码（十六进制，可组合）：

| 位 | 含义 |
|---|---|
| 01 / 02 / 04 / 08 | M1 / M2 / M3 / M4 |
| 10 | 位置控制超时 |
| 20 | 方向反馈异常，通常同时置轮位 |
| 40 | 编码器非法跳变，通常同时置轮位 |
| 80 | 位置进度同步异常 |

已有 `DRV` 日志每秒输出 `F`（十进制）、电压 `V`、同步差 `SP` 和
各轮 `目标/实测/PWM`。驱动故障分支在日志调用之后，因此故障锁存后仍可
由集成任务在另行获得硬件授权时读码。本任务未访问任何端口。
丢线恢复本身到达局部尝试次数或 8 秒上限只给停止命令，不自行鸣笛。
不要关闭故障锁存或自动清错重试来掩盖当前报警。

## 离线证据与集成要求

`tests/line_recovery/run.cmd` 包含两档原恢复回归（2493 / 1870 CPS）和
真实 DriveBase + 真实寻线/恢复 + 补偿模块测试，仅模拟编码器、电池和 PWM 引脚。
编译使用 MSVC `/W4 /WX`，PWM 上限直接使用正式 motorPWM.h，删除了
原测试桩中错误的 7199 上限。

确定性欠速输入下，正常弯道滞后轮输出从 2468 增至 3068；对转时从
2905 增至 3505（逆向同样对称）。其他三个达到目标的轮子输出不变，
请求 CPS 完全不变。这是软件控制证据，不是实车摩擦或电流测试。
另验证超速撤补偿、短暂误差不触发、斜坡/低速禁用、授权消费/过期、
普通相同目标撤销、目标被限速后失配、停车/位置所有权、堵转锁存、
方向与编码器故障、位置超时、时钟回绕。

由“黑线避障”集成任务只 cherry-pick 本轮增量，保留它自己的其他修改，
重新编译并生成集成固件；不要直接使用本工作树 BIN 替换集成固件。
本工作树不包含集成任务后来独立加入的蜂鸣器 GPIO 修复。
现场验证尚未进行：新旧地面、左右弯、单轮滞后、脱困后过冲、丢线漂移，
以及本次 KEY2 停机的实际故障码均需集成任务后续确认。
