# 丢线持续旋转，确认见线后静音并恢复寻线

用户最新要求取消丢线超时停车，并明确找回黑线后自动恢复寻线和停止蜂鸣。
本轮接续工作分支 `90381ee24c8949a422890cdc4c57991d2d7bb0e4`，该分支祖先为
`2a7a5d5611928205137df858b448086f34685821`。

## 行为

1. 丢线先短暂制动，然后按近期有效方向提示持续同向旋转；没有有效提示时默认左搜。
   同侧两轮目标相同、左右符号相反，默认幅值 2493 CPS；90 度/秒名义对照为 1870 CPS。
   这些是编码器轮速目标，真实车身转速和旋转中心尚未实测。
2. 删除回退、分级扫描、返回原计数、搜索距离/次数限制、8 秒搜索超时和恢复层
   无进展停车。全白持续多久都不会仅因搜索预算耗尽而停下或交换搜索方向。
3. 复用现有非阻塞 `BuzzerPhrase400`，每次播放一个 1530 ms 预制节奏，结束后重新播放。
   不受单次 API 最多 24 次重复的限制，不改变共享蜂鸣模块和主循环。
4. 内侧 X1 或 X3 见黑且两个外侧不同时见黑，先制动，再连续确认 20 ms。
   确认后静音，进入至少 500 ms 的低速接线；内侧稳定 80 ms 后恢复正常速度。
   不再以旧 800 ms 捕线超时停止。误触线未确认时，最多等待 80 ms 后继续旋转。
5. 接线阶段再次全白，重新开始旋转并播放预制蜂鸣。外侧单独见黑和四路全黑不会
   在旋转阶段直接判为成功捕线。
6. 遥控停止/模式切换沿用主循环的停止、寻线 reset 和蜂鸣取消路径；启动仍是 STOP。
   KEY1 从未见线时的既有前行策略、避障优先级和 KEY2 寻线模式选择不变。
7. 后续用户要求寻线故障只记录不停机，当前配套行为见
   [故障观察与 RAM 日志](FAULT_OBSERVATION.md)。寻线速度模式的无响应、方向和编码器
   信号判定改为记录并继续；方向/信号异常轮改用基础 PWM，单独无计数保留限幅助力。
   其他模式的阻断故障仍保留。

## 验证

- `cmd /c tests\line_recovery\run.cmd`：MSVC /W4 /WX，默认和低速两种配置，
  各覆盖 smooth 开/关及两种无线路径；90 秒模拟持续搜索、反复丢线、误触线、
  长时间外侧见线、超旧捕线期限后回归正常、停止/reset 取消、故障锁存和 tick 回绕。
- 测试链接真实预制蜂鸣模块，验证 GPIO 的 110/30/150/10/140/60/170/12/280/568 ms
  节奏以及循环续播、成功捕线静音和正常手动播放的所有权边界。
- 实际 `drive_base.c` 与 PWM/计数模拟模型联合回归：90 秒搜索后捕线、
  负载补偿、租约失效、超速抑制、位置/连续输出交接，以及真实无响应/方向/编码器故障。
- `python tests\line_recovery\calculate_search_geometry.py --self-test`：尺寸换算和合成 ICR 反解。
- 正式构建使用仓库 `build_unified_motion.ps1`，产物/hash 和最终结果记录在交接包。

以上是主机模拟和编译验证，不是实际遥控、架空或落地测试。持续旋转仍可能因侧滑
离开赛道；软件同侧等速不能保证几何中心原地旋转，也不保证任意地面都能重新找回黑线。
