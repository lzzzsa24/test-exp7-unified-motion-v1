# 回退进入低速脉冲区时撤销持续 PWM

用户现场现象：KEY2 丢线后短暂后退，再次碰到黑线附近时左 RGB 变黄、
蜂鸣，小车保持停止。尚未取得每组蜂鸣次数或 `DRV F=`，不能把软件
复现直接等同于这一次现场报警的最终根因。

## 合并核对

`63dbfe6` 的寻线、恢复、负载补偿、DriveBase、头文件及测试完全相同。

本地固件哈希与记录一致。没有发现漏合并、覆盖寻线文件或集成冲突。

以下缺陷在本工作分支提交 `208948c` 上已经存在，不是此次集成造成的。

## 已复现的缺陷

DriveBase 的位置模式在剩余行程小于 180 编码器计数，或速度低于连续
运行下限时，改用短脉冲。脉冲服务要求先满足停稳条件，才启动下一脉冲。
旧代码切换 `position_low_mode` 后跳过持续速度输出，却没有将上一周期
已经施加的 PWM 清零。因此轮子可能一直受力，停稳等待无法完成，越过
目标、位置超时或轮间进度异常都存在可能。

真实 DriveBase 的确定性回归：四轮目标各 -316，最大 2493 CPS；
首周期持续回退后，M1 剩余 -166，另外三轮仍在持续运行区。
旧代码读出 M1 `PWM=-2559`，断言 `pins[0]==0` 失败，测试退出码 1。
这是位置输出交接的直接反例，与传感器读数或是否经过合并无关。

## 修复

- 切入低速脉冲模式时，撤销该轮之前的持续 PWM。
- 对这次被撤销的连续输出重新建立停稳窗口，并沿用 36 ms 间隔和
  各轮 25 ms 错峰，使正在滑动的车轮不会立即收到新脉冲。
- 脉冲与持续模式切换时，取消旧脉冲响应窗口，避免将后续持续运动
  计入上一段已经中断的脉冲。
- 启动时原本为零的输出不重排既有脉冲起步时序。
- 保留四轮目标、位置容差、同步等待、故障阈值和故障锁存，
  不自动清错，不扩大寻线回退范围，不改 RGB 或蜂鸣映射。

## 验证

- 上述旧代码失败案例修复后 M1 `PWM=0`；其余三个仍处于持续区的轮子
  保持原方向输出。
- 正向/反向两种位置动作均覆盖连续到脉冲切换、短时惯性位移保持零输出、
  进度领先轮等待其他轮追上、停稳后的短脉冲重启、显式刹车中断及完成。
- 新增真实 `line_tracking.c + line_recovery.c + drive_base.c` 联动测试：
  丢线、真实位置回溯、内侧传感器见线、刹车、低速确认、恢复正常前进。
  仅模拟 PWM 引脚到编码器计数，不模拟真实轮胎与地面，不能证明实车转角或漂移。
- 原 2493 / 1870 CPS 恢复回归及全部欠速补偿/故障锁存回归继续运行。

这个修复位于共享位置内环，因此位置控制调用者都会得到正确的模式交接；
它不是只对寻线动作加特判。集成时应保留其他模式原有配置，并关注其短距离
位置收尾行为。现场是否正是这条路径触发报警，还需由集成任务取得故障码
并验证修复后的回退、碰线和恢复动作。
