# KEY3 编码器闭环 8 字模式

> 本文件保留历次8字标定背景；统一执行层、停车策略、当前模式映射和
> 软件验证状态以 `README_UNIFIED_MOTION.md` 与
> `REFACTOR_VERIFICATION.md` 为准。

本工程由 `test-exp7-no-line-auto-avoid-ultrasonic` 独立复制而来，原工程未修改。

## 三个锁存模式

- KEY1：原综合模式（循迹、红外、超声波；K210 暂时禁用）。
- KEY2：仅寻线模式。
- KEY3：一次性编码器闭环8字。依次完成左圆、暂停100 ms、右圆，然后自动停车。
- 按下另一个按键即可退出当前模式；松开按键不会改变已经选择的模式。

板载 HS0038B 红外接收头也可选择相同模式：遥控数字 `1` 等效 KEY1，
数字 `2` 等效 KEY2，数字 `3` 等效 KEY3。采用 NEC 解码后的修正键码
`0x10/0x11/0x12`，长按重复帧不会反复切换模式。遥控器需要对准开发板
上的黑色红外接收头，而不是车头的红外避障探头。

遥控数字 `0` 是锁存停车键，命令值为 `0x0D`：会立即终止 8 字、循迹和
避障电机动作，OLED 显示 `MODE:STOPPED`，两个诊断 LED 常亮。停车后短按
遥控 `1/2/3` 或实体 KEY1/KEY2/KEY3 才会进入相应模式；长按重复帧不会
解除停车。

第一次烧录后必须先把四个轮子架空。KEY3 模式中：左 RGB 绿色表示左圆、蓝色表示右圆、紫色表示循环间暂停、红色表示故障；右 RGB 主动保持熄灭，避免和红外状态混淆。LED1 表示左圆，LED2 表示右圆；两灯同时亮表示程序已经因编码器断线、车轮失速或单圈超时停止电机。

故障时蜂鸣器不再持续鸣叫，而是每组鸣叫 1～5 声：1～4 声分别对应 M1～M4 没有脉冲，5 声表示圆弧运行超时。若多个编码器同时异常，先报告编号最小的一路；修复后重新按 KEY1 再按 KEY3 复测。

## 编码器接口

开发板原理图确认的网络如下：

| 电机 | A 相 | B 相 |
|---|---|---|
| M1 | PD12 / H1A | PD13 / H1B |
| M2 | PA15 / H2A | PB3 / H2B |
| M3 | PA0 / H3A | PA1 / H3B |
| M4 | PB4 / H4A | PB5 / H4B |

每个 6 针电机口顺序为 `M+、M-、GND、3V3、B、A`。四路 AB 相由 TIM6
以 20 kHz 采样并做 Gray 码解码。2026-09-04 的 M2 专项实测确认：旧
`PD7/PB3` 映射只有 B 相变化；正确 `PA15/PB3` 映射正转得到 A/B 边沿
`1939/1939`、Q=`+3878`，反转得到 `1933/1934`、Q=`-3867`，非法跳变
为 0。因此当前四轮均使用完整 AB 正交解码，不再保留 M2 单通道降级。

PA15/PB3/PB4 默认属于 JTAG；`HAL_MspInit()` 已关闭 JTAG、保留 SWD，
使这些引脚可作编码器输入。编码器并不占用 PE2～PE5；退出轨迹模式时仍
会防御性恢复 RGB/红外 GPIO 并保留红外标定。KEY3 模式不会运行循迹、
红外、视觉或超声波电机控制，避免多个状态机互相覆盖。

## 8 字闭环

- KEY3不再维护另一套近似转弯算法，而是复用统一的 `EncoderTurn` 模块。
- 左环调用`EncoderTurn_Start(+360000, +220, 2357)`，右环调用
  `EncoderTurn_Start(-360000, -220, 2357)`；角度和半径同号，因此两个
  环都沿车体前进方向运行，且左右内外轮真正交换。
- 两个完整360°圆在起点相切，左环结束主动制动并暂停100 ms，再执行
  右环；右环结束后自动锁存停车，适合拔掉USB后的离线测试。
- 当前等效轮距约338 mm，中心半径220 mm时内外轮都向前，避免旧版
  小半径命令内轮反转造成原地扭动。
- 四轮分别执行目标counts/s和目标位置；连续区使用PI，低速内轮和末端
  使用编码器位置脉冲，并带同步、主动制动、失速和超时保护。
- 诊断串口在KEY3期间每200 ms输出`FIG8 S=... F=... M1=... M4=...`，便于
  连线判断左环、右环、暂停和故障。

旧版独立8字控制器保存在
`Core/Src/figure8_encoder_before_precise_turn.c.bak`，不会参与编译。
2026-09-03实测：轮径47 mm、左右轮距129 mm、前后轴距129 mm。
结合既有地面转角数据，转向模型使用约338 mm的滑移补偿等效轮距。
KEY3两圆中心半径为220 mm，理论占地约880 mm x 440 mm；四轮全程同向前进，
避免旧版113 mm半径下内侧轮反转造成的“原地扭动”。编译成功仍不代表
地面8字已经闭合，需以实车轨迹为准。

## 四电机功率标定

已重新烧录自动标定固件，在每轮独立清零且不接触轮胎的条件下完成
1800、2200、2400、3000 四个速度点共 33 轮原始/复测。电机低速响应
明显非线性，因此改用 2200/2400/3000 三节点分段 PWM 映射，不再使用
单一千分比。

补偿后在 2200、2400、3000 三个有效工作点，四轮平均计数的最快/最慢
差分别为 0.71%、0.82%、0.22%。PWM=1800 时四轮均无法起转，因此综合
工程的超声慢速、限速和八字最低 PWM 已提高到 2200。完整原始数据、
映射值和证据边界见 `MOTOR_POWER_CALIBRATION_20260903.md`。

## 编码器速度闭环

KEY3 已增加四轮独立 PI 速度环：每 20 ms 读取编码器增量，分段功率标定
作为前馈，PI 负责消除电池和负载变化造成的剩余误差。停车、暂停和换向
都会清除积分，单轮修正量限制为 ±500 PWM。

四轮悬空实测中，2200/2400/3000 三个速度点的单轮3秒累计目标误差均
小于 0.9%；PWM=2400 四轮同时运行三轮时，各轮相对目标误差不超过
0.32%，最快与最慢轮平均差约 0.63%。详细数据见
`ENCODER_SPEED_CONTROL_20260903.md`。

统一运动工程中，KEY1/KEY2 的黑线传感器控制作为外环输出左右目标 CPS，
再由 DriveBase 四轮独立编码器速度内环执行；KEY3 和数字4的短距离、
低速内轮及末端接近则由统一的位置反馈脉冲与四轮进度同步执行。

## 编码器精确角度转向

遥控/串口数字 `4` 执行一次400 mm边长、四个90°转角的正方形，数字 `0`
可随时停车。正方形及八字共用通用接口
`EncoderTurn_Start(angle_mdeg, center_radius_mm, maximum_wheel_cps)` 会根据
轮径、轮距和转弯半径计算左右路径长度与四轮目标速度，再由四路速度 PI
分别执行。

针对落地动力不足和板载驱动 0/0 停车后的惯性滑行，末端使用按每轮实际
编码器响应自适应的5～28 ms位置脉冲；BRAKE先执行30 ms换向保护，再施加
最多22 ms、逻辑PWM 2400的反向转矩，然后恢复0/0。
完整公式、补偿和证据边界见 `ENCODER_PRECISE_TURN_20260903.md`。

地面第一次90°命令目测约40°，将目标计数按`90/40=2.25`修正后，第二次
有载荷测试由用户目测约90°。该系数是当前场地的经验值，不是真实轮距。
随后三次累计目测约260°而目标为270°，经验系数进一步修正为约2.337。
降低右前轮脉冲功率后的三次累计约265°，最终平均角度参数微调为352；
单次角度仍会因四轮侧滑产生随机差异。

## 连线有载荷调试

上电和烧录后的默认状态已改为锁存停车，不再自动进入KEY1综合模式。
诊断串口使用115200 8N1（COM号以设备管理器当前枚举为准），可直接发送
单字符命令：`0`停车、`1`综合、`2`纯寻线、`3`八字、`4`正方形。轨迹期间回传
状态、故障掩码和M1～M4累计编码器计数，便于保持连线进行地面调试。

## 实测顺序

1. 车轮离地，按 KEY3；确认四轮都向前转，LED1/LED2 随左右圆阶段切换。
2. 若进入红灯故障，1～4 声依次表示 M1～M4 无有效脉冲，5 声表示轨迹控制超时；OLED 同时显示故障掩码和四轮计数。
3. 轮子离地完成一次完整 8 字后，按 KEY1，确认退出 KEY3，RGB/红外恢复。
4. 地面测试必须在至少 2 m x 1.5 m 的无遮挡区域低风险进行，手放在电源开关旁。
5. 若左右圆都过大或过小，先测一圈编码器计数；若一圈计数正确，再调整 `FIG8_LOOP_CENTER_RADIUS_MM`。

完成实体按键测试后，再让轮子离地，短按遥控数字 `2`、`1`、`3`，确认
分别进入仅寻线、综合、8 字模式。数字 `3` 会立即启动电机；随后按数字 `0`
确认四轮立即停止且 OLED 显示 `MODE:STOPPED`，再按 `1/2/3` 恢复。

## CubeMX 注意

统一运动工程的 `.ioc` 已记录 TIM6 和八个编码器 GPIO，但当前经过验证的
启动路径仍由 `wheel_encoder.c` 手动配置 TIM6。CubeMX 重新生成前必须先
备份，并将新生成的 `MX_TIM6_Init()` 与手动初始化二选一，不能保留两套
TIM6 初始化或两个 `TIM6_IRQHandler`。
